\section{Design Process and Methodology Overview}

The study tests different ways of showing the visual representation to the model and each task uses its own evaluation model. Each task has an RGB reference model and a cattle-centered version. These six single-task models establish task-specific performance baselines and serve as the empirical reference for evaluating three multi-task learning configurations: a monolithic hard-shared control architecture (E1), a modular task-private architecture (E3), and a gradient-projected hard-shared optimization control (E4).

The main design question is what information each task should receive. BCS mainly needs morphology, behavior recognition needs posture and temporal change, and Re-ID needs stable individual appearance. Because of this, the cattle-centered models all focus on the target cow, but they do not use exactly the same preprocessing. Figure~\ref{fig:phase3design} shows the overall comparison, and Table~\ref{tab:runstatus} lists the model configurations. Supporting records are indexed in Appendix~\ref{app:evidence}.

The perception enhanced models perform a number of modifications simultaneously. In BCS, the architecture modifies localization, cropping, and also uses mask information. In behavior recognition, the architecture modifies visual features and the temporal aggregation strategy. In Re-ID, the architecture modifies crop geometry and introduces an oracle mask channel. Thus, these comparisons evaluate the performance of a complete model architecture, but they cannot provide us with the effect of each component independently. The backbone of reference RGB models is a common ImageNet pretrained ResNet-18 for all three tasks.

\subsection{Representation Alternatives}

However, for each task, a different prediction head is used: cumulative ordinal logits for BCS, categorical logits for behavior recognition, and an identity classifier with retrieval embedding for Re-ID. The task protocol remains the same to allow the more meaningful comparison between RGB and cattle-centered input.

We chose the localization and segmentation approaches based on the experiments with pretrained perception models. The success rate of detection and duration of the process were estimated during the research. Mask overlap was estimated in cases where ground-truth masks of SideView were available. The RT-DETR-L and subsequent SAM 2.1 served as a convenient automatic pipeline for ScienceDB and Behavior data. \subsection{Baseline RGB Body Condition Scoring}

The BCS baseline uses an ImageNet-initialized ResNet-18 with four independent cumulative threshold logits for five ordered classes. For a class index $y\in\{0,1,2,3,4\}$, the target for threshold $k$ is
\begin{equation}
 t_k=\mathbb{I}(y>k),\qquad k=0,1,2,3.
\end{equation}
If $g_k=\mathbf{w}_k^\top\mathbf{h}+b_k$ is the corresponding logit, the batch loss is
\begin{equation}\label{eq:bcs_loss}
 L_{\mathrm{BCS}}=-\frac{1}{4B}\sum_{i=1}^{B}\sum_{k=0}^{3}
 \left[t_{ik}\log\sigma(g_{ik})+(1-t_{ik})\log(1-\sigma(g_{ik}))\right].
\end{equation}
The predicted class is found by counting how many threshold probabilities are above 0.5. It is then mapped back to the physical BCS scale:
\begin{equation}
 \hat y=\sum_{k=0}^{3}\mathbb{I}(\sigma(g_k)>0.5),\qquad
 \widehat{\mathrm{BCS}}=3.25+0.25\hat y.
\end{equation}
The targets are cumulative, but the model uses independent ordinal binary cross-entropy. Therefore, the method is described as \texttt{ordinal\_bce}, not CORAL, because CORAL uses a different rank-consistency method~\cite{coral2020}. The model was trained for 30 epochs with batch size 64, AdamW, an initial learning rate of $10^{-4}$, weight decay $10^{-4}$, a cosine learning-rate schedule, and seed 42. The checkpoint with the lowest validation MAE was kept.

\subsection{Perception-Enhanced Body Condition Scoring}

The perception-enhanced BCS model first localizes and segments the cow in ScienceDB. RT-DETR-L detects cattle using the COCO cattle class with a confidence threshold of 0.25. If more than one cow is detected, the largest bounding box is selected, and confidence is used to break a tie. The selected box is expanded by 5\% in each direction, clipped to the image boundary, and used for both the RGB crop and the SAM 2.1 prompt. If detection or segmentation fails, the image is recorded as a perception failure and excluded. No artificial replacement input is used.

The RGB crop and binary mask are resized together to $224\times224$. The RGB channels use ImageNet normalization, while the mask stays as an unnormalized binary channel in $\{0,1\}$. The first ResNet-18 convolution is changed from three input channels to four. The pretrained RGB weights are kept, and the new mask-channel weights are initialized using the mean of the RGB filters. The ordinal head, target encoding, loss, training schedule, and augmentation policy otherwise follow the RGB BCS baseline. This adds 3,136 trainable parameters, increasing the model from 11,178,564 to 11,181,700 parameters. The model uses a binary mask channel; it is not a calibrated soft-mask model.

\subsection{Baseline Single-Frame RGB Behavior Recognition}

Pose and viewpoint were not added to the first paired models since their utility and transferability for the tasks had not been proven. It should be noted that this does not exclude them from further separate ablation studies. Behavior uses the middle frame of each canonical sample. The ImageNet pretrained ResNet-18 is employed together with a five-class linear classifier. Five classes are Standing, Lying, Feeding, Drinking, and Walking. The model is trained using cross-entropy loss. For the CVB, the target tracklet information obtained from the dataset is used, and Kaggle Beef provides one cow for each clip.

Out of the 30 trained epochs, epoch 25 is selected as the checkpoint with respect to the Macro-F1 score in the validation. The baseline does not have any kind of temporal aggregation intentionally; it seeks to see what is the extent of information that can be derived from just one RGB frame in a regular five-class scenario. This is why the performance metrics include overall accuracy, balanced accuracy, and class-specific results. The significance of this point is the fact that Walking is present only in the CVB dataset.

\subsection{Perception-Enhanced Temporal Behavior Recognition}

The temporal behavior model uses eight approximately evenly spaced frames from each labeled interval instead of only the midpoint frame. Its input tensor has shape $[B,8,4,224,224]$. Each time step contains an RGB crop and a binary mask. For CVB, the target-tracklet box at the sampled frame is used to prompt SAM 2.1, and the same box is used for the RGB and mask crops. The model does not replace the target with a nearby cow or with the full image. For the single-cow Beef clips, RT-DETR-L provides the main cow box when available, followed by a positive center prompt to SAM 2.1. If the detector finds no cow, an image-center prompt is used. A sequence is excluded if any required mask is empty or invalid.

The training and validation cache kept 4,271 of 4,465 candidate sequences: 3,641 for training and 630 for validation. It contains 34,168 RGB frames and 34,168 non-trivial binary masks. There were 194 exclusions because of empty-mask failures, and all 145 Walking candidates in training and validation were kept. The held-out test comparison separately kept 780 of 809 samples, including 422 CVB and 358 Beef sequences.

First, each frame is transformed using a four-channel ResNet-18, and hence a feature vector of 512 dimensions is obtained. The sequence H is [B, 8, 512] in size and is first transposed and then used for the temporal convolution. For the first Temporal block, Conv1D with kernel size three is used to down project the channel sizes from 512 to 256. Following that, BatchNorm, GELU, Dropout 0.2, and one-width residual projection come up. In the second Conv1D block, the kernel size used is three and the feature size is of 256 channels. Normalization, activation, and dropout are applied along with identity residual. Adaptive average pooling along the time axis leads to one 256-dimensional feature vector which feeds into the linear classifier of five classes. The model being proposed here is a light residual Conv1D model which accepts sparsely sampled frame features but does not use optical flow, video transformer or deep dilated causal TCN.

\subsection{Baseline RGB Cattle Re-Identification}

The total number of trainable parameters in the model is 11,903,621. For RGB Re-ID, the SideView Protocol A is used in the baseline. To learn representation, 41 cows are selected from parlor only. 12,753 training and 2,683 validation images are used. The total evaluation is performed on 69 different cows. Gallery images are 36,811 of parlor. Barn query consists of 25,260 images of all the 69 cows. On the other hand, snapshot query consists of 607 images of 63 cows. The cows for representation learning and evaluation are distinct.

ResNet-18 produces a raw 512-dimensional feature $\mathbf{h}$. A 41-class linear classifier is trained on this feature with cross-entropy loss. Retrieval uses the L2-normalized version:
\begin{equation}
 \mathbf{z}=\frac{\mathbf{h}}{\lVert\mathbf{h}\rVert_2},\qquad
 \boldsymbol{\ell}=W\mathbf{h}+\mathbf{b}.
\end{equation}
During evaluation, cosine similarity is calculated as the dot product between normalized query and gallery embeddings. Gallery images are ranked for each query, and performance is reported using Rank-$k$ and mean average precision (mAP). The model was trained for 30 epochs, and the validation-selected representation was evaluated once under the held-out Protocol A conditions.

\subsection{Oracle Segmentation-Guided Re-Identification}

For the segmentation-guided Re-ID model, since the ground-truth masks of the target cows are provided by SideView, the experiment is oracle-based. The non-zero area of each mask is used to generate a bounding box which is then padded to be slightly larger than the mask by about 5\%. The same box coordinates are employed to crop the RGB image and the mask. They are then resized to 224x224. The RGB image is normalized with ImageNet values whereas the mask is binary having values of 0 and 1. The RGB image is not multiplied with the mask. The first convolution layer is modified to receive four input channels. The filter parameters for the newly added mask channel are initialized using the average of RGB filter parameters.

This comparison tests whether reliable target-centered cropping and explicit foreground information help cross-setting retrieval. It does not test an automatic segmentation pipeline, and it does not separate the effect of cropping from the effect of the fourth channel. The extra 3,136 weights increase the trainable parameter count from 11,197,545 to 11,200,681.

\section{Implementation of Selected Design}

 The checkpoint was picked up solely on the basis of results on validation sets, while test sets remained entirely out of training and model selection. All configuration parameters, losses per epoch, check points' checksums, and evaluations rankings are stored in machine-readable manifests to enable scientific reproducibility.

\subsection{Monolithic Hard-Shared Multi-Task Control Architecture}

A monolithic hard-shared multi-task model (E1) is used as a baseline for parameter sharing between the three tasks. In this case, all three tasks share a single spatial feature extractor, i.e., four-channel ResNet-18, as their backbone.

The model accepts task-specific input tensors whose spatial dimensions are standardized to $224 \times 224$ pixels across four channels, comprising three ImageNet-normalized RGB channels and one unnormalized binary cow mask:
\begin{align}
 \mathbf{X}_{\mathrm{BCS}} &\in \mathbb{R}^{B_{\mathrm{BCS}} \times 4 \times 224 \times 224}, \\
 \mathbf{X}_{\mathrm{Beh}} &\in \mathbb{R}^{B_{\mathrm{Beh}} \times 8 \times 4 \times 224 \times 224}, \\
 \mathbf{X}_{\mathrm{ReID}} &\in \mathbb{R}^{B_{\mathrm{ReID}} \times 4 \times 224 \times 224}.
\end{align}
The shared spatial backbone maps each four-channel frame to a 512-dimensional embedding $\mathbf{h} \in \mathbb{R}^{512}$. Each task then routes this representation to its task-specific prediction head:
\begin{enumerate}
 \item \textbf{Body Condition Scoring}: Body Condition Scoring: The common feature $\mathbf{h}$ is passed to a cumulative ordinal linear head with 2,052 parameters. Four independent logits of thresholds for k values of 0, 1, 2, and 3 are produced by the BCS model. The training of the BCS model is conducted with the help of ordinal binary cross-entropy loss ($L_{\mathrm{BCS}}$).
 \item \textbf{Cattle Behavior Recognition}: Cattle Behavior Recognition: The same four-channel ResNet-18 spatial backbone is used to process each frame of 8 in the video sequence. The output frame features H have the shape of [$B_{\mathrm{Beh}}$, 8, 512]. This sequence is further passed to the TCN head, which has 723,973 parameters. This includes two Conv1D residual blocks with a kernel width of three and 256 channels, together with BatchNorm, GELU, and dropout of 0.2. After that, a 256 dimensional feature is extracted by temporal adaptive average pooling. This feature is then passed to a five-class linear classifier. The Behavior model is trained using categorical cross-entropy loss ($L_{\mathrm{Beh}}$).
 \item \textbf{Individual Cattle Re-Identification}: Re-Identification of Individual Cattle: In the representation learning part, the standard 512 dimensional h is passed into the 41-class linear classification model with bias having the 41 identities used for the parlor training as the goal. The model has 21,033 trainable parameters and trained using cross-entropy loss ($L_{\mathrm{ReID}}$). During the open-set retrieval evaluation on novel cattle, embeddings are L2 normalized to have a unit norm.
\end{enumerate}
The monolithic hard-shared multi-task control contains exactly 11,926,706 trainable parameters.

\subsection{Modular Task-Private Multi-Task Architecture}

The monolithic hard-shared multi-task model consists of 11,926,706 trainable parameters exactly. In the modular task-private multi-task model (E3), we intend to see if an increase in the capacity of the model specific to each task helps in overcoming the negative transfer without changing the shared visual model architecture. The model is made identical in all aspects of the backbone architecture, task heads, inputs, datasets, batch size, loss function, optimizer, training budget, and model checkpoint except that there are three task-private residual adapters used in the model. This leads to an increase in the number of trainable parameters by 395,904 (3.32\%). As such, the variations noted herein are the result of full modularization, which is not possible due to routing alone. Figure~\ref{fig:mtl_architecture_comparison} illustrates the structural comparison between the monolithic hard-shared version against the modular task-private E3 version. The hard-shared version also forms the exact architecture used for E4. Also shown in the diagram is the bottleneck adapter design utilized by E3.

\input{images/mtl_architecture_comparison}

The architectural modification consists of inserting one independent residual bottleneck adapter between the shared 512-dimensional representation $\mathbf{h}_{\mathrm{shared}} \in \mathbb{R}^{512}$ and each respective task head. For task $t \in \{\mathrm{BCS}, \mathrm{Beh}, \mathrm{ReID}\}$, the adapter consists of:
\begin{enumerate}
 \item A linear down-projection from 512 to 128 dimensions with weights $\mathbf{W}_{\mathrm{down}}^{(t)} \in \mathbb{R}^{128 \times 512}$ and bias $\mathbf{b}_{\mathrm{down}}^{(t)} \in \mathbb{R}^{128}$;
 \item Layer normalization over the 128-dimensional bottleneck;
 \item A GELU activation function followed by dropout ($p = 0.1$);
 \item A linear up-projection from 128 back to 512 dimensions with weights $\mathbf{W}_{\mathrm{up}}^{(t)} \in \mathbb{R}^{512 \times 128}$ and bias $\mathbf{b}_{\mathrm{up}}^{(t)} \in \mathbb{R}^{512}$.
\end{enumerate}
The adapter output $\Delta\mathbf{h}_t \in \mathbb{R}^{512}$ is added residually to the shared spatial representation to produce the task-adapted feature $\mathbf{h}_t$:
\begin{equation}
 \mathbf{h}_t = \mathbf{h}_{\mathrm{shared}} + \Delta\mathbf{h}_t.
\end{equation}
In the temporal behavior model, this adapter operates frame-wise on each of the 8 temporal feature vectors before the adapted sequence $\mathbf{H}_{\mathrm{Beh}} \in \mathbb{R}^{B_{\mathrm{Beh}} \times 8 \times 512}$ is routed to the temporal convolutional network.

Each task-private adapter contains exactly 131,968 parameters, yielding 395,904 total private parameters across the three tasks (3.21\% of the model's total parameters). The modular multi-task architecture comprises 12,322,610 trainable parameters, representing an increase of 395,904 parameters (+3.32\% relative capacity) over the hard-shared control.

\subsubsection{Identity Initialization of Residual Adapters}

The up-projection layer of each task adapter is initialized with zero weights and zero biases:
\begin{equation}
 \mathbf{W}_{\mathrm{up}}^{(t)} = \mathbf{0}, \qquad \mathbf{b}_{\mathrm{up}}^{(t)} = \mathbf{0}.
\end{equation}
At step zero of training, this ensures that the adapter contribution is strictly zero:
\begin{equation}
 \Delta\mathbf{h}_t = \mathbf{0} \implies \mathbf{h}_t = \mathbf{h}_{\mathrm{shared}}.
\end{equation}
This initialization does not imply inheriting representations from a pretrained hard-shared checkpoint; rather, it guarantees that at the start of joint training, each task-specific head receives the direct, unperturbed output of the modular model's own shared backbone. Task-private feature specialization $\Delta\mathbf{h}_t$ then develops progressively as gradient updates accumulate during training.

\subsection{Gradient-Projected Hard-Shared Multi-Task Optimization}

In the third multi-task model, which is known as E4, the researchers evaluate whether the gradient conflict decrease during optimization process might lead to the decrease in negative transfer while keeping the architecture of the model unchanged. Thus, E4 does not acquire any extra architectural capabilities. E4 keeps the same parameter structure as the monolithic hard-shared model E1. There is one shared four-channel ResNet-18 spatial backbone (11,179,648 parameters) along with the same three task-specific prediction heads (747,058 parameters). The latter ones are the following: BCS ordinal head, Behavior 1D TCN, and Re-ID classification head. So, E4 has exactly 11,926,706 trainable parameters, without task-private adapters and without routing gates. All the training datasets, input formats, batch sizes, task losses, optimizer parameters, learning rate schedules, task loss weights, and checkpoint selection policies are kept strictly the same as E1.

The controlled experimental intervention in E4 resides exclusively in how task-specific gradients are combined on the shared backbone parameters $\boldsymbol{\theta}_{\mathrm{shared}}$ during each multi-task training super-step. When training multi-task networks with hard parameter sharing, backward passes from distinct task losses frequently produce gradient vectors that point in conflicting directions, such that the gradient update for one task increases the loss of another~\cite{yu2020pcgrad}. To address this, E4 applies Projecting Conflicting Gradients (PCGrad; Yu et al., 2020) to the shared backbone gradients.

The controlled experimental intervention in E4 resides exclusively in how task-specific gradients are combined on the shared backbone parameters $\boldsymbol{\theta}_{\mathrm{shared}}$ during each multi-task training super-step. When training multi-task networks with hard parameter sharing, backward passes from distinct task losses frequently produce gradient vectors that point in conflicting directions, such that the gradient update for one task increases the loss of another~\cite{yu2020pcgrad}. To address this, E4 applies Projecting Conflicting Gradients (PCGrad; Yu et al., 2020) to the shared backbone gradients.

Within each super-step, three backward passes first compute task-specific gradients on the shared backbone:
\begin{equation}
 \mathbf{g}_{\mathrm{BCS}} = \nabla_{\boldsymbol{\theta}_{\mathrm{shared}}} L_{\mathrm{BCS}}, \qquad
 \mathbf{g}_{\mathrm{Beh}} = \nabla_{\boldsymbol{\theta}_{\mathrm{shared}}} L_{\mathrm{Beh}}, \qquad
 \mathbf{g}_{\mathrm{ReID}} = \nabla_{\boldsymbol{\theta}_{\mathrm{shared}}} L_{\mathrm{ReID}}.
\end{equation}
The task gradient vectors are evaluated pairwise in a randomized order deterministically shuffled at each step using random seed 2026. For task $i$ and comparison task $j$ ($i, j \in \{\mathrm{BCS}, \mathrm{Beh}, \mathrm{ReID}\}$, $i \neq j$), directional conflict is determined by the sign of their inner product. If
\begin{equation}
 \mathbf{g}_i^\top \mathbf{g}_j < 0,
\end{equation}
the two gradients point in opposing directions. The gradient vector $\mathbf{g}_i$ is then projected onto the normal plane of $\mathbf{g}_j$:
\begin{equation}
 \mathbf{g}_i \leftarrow \mathbf{g}_i - \frac{\mathbf{g}_i^\top \mathbf{g}_j}{\lVert\mathbf{g}_j\rVert_2^2 + \epsilon} \mathbf{g}_j,
\end{equation}
where $\epsilon = 10^{-8}$ is a small constant for numerical stability. In accordance with the PCGrad formulation~\cite{yu2020pcgrad}, the comparison vector $\mathbf{g}_j$ is the original, unmodified task gradient to prevent order-dependent distortion of the reference direction. If $\mathbf{g}_i^\top \mathbf{g}_j \ge 0$, no projection is applied.

Once all pairwise projections are complete, the resulting modified shared gradients $\mathbf{g}'_{\mathrm{BCS}}$, $\mathbf{g}'_{\mathrm{Beh}}$, and $\mathbf{g}'_{\mathrm{ReID}}$ are summed to form the unified update vector for the shared parameters:
\begin{equation}
 \mathbf{g}_{\mathrm{shared}} = \mathbf{g}'_{\mathrm{BCS}} + \mathbf{g}'_{\mathrm{Beh}} + \mathbf{g}'_{\mathrm{ReID}}.
\end{equation}
Gradients are added together instead of being averaged in order for the experiment to remain consistent with the baseline model (E1). In the baseline model, the gradients are combined based on a weight of 1 for each task. Consequently, any deviations from the training regime can be attributed to the gradient projection method and not the learning rate.

Each task gets its unique prediction head, which is not shared between tasks. That is why, their gradients will not interfere with one another. For this reason, PCGrad is only applied to the shared ResNet-18 backbone, while the gradients of task heads remain untouched:
\begin{align}
 \mathbf{g}_{\mathrm{head}}^{(\mathrm{BCS})} &= \nabla_{\boldsymbol{\theta}_{\mathrm{head}}^{(\mathrm{BCS})}} L_{\mathrm{BCS}}, \\
 \mathbf{g}_{\mathrm{head}}^{(\mathrm{Beh})} &= \nabla_{\boldsymbol{\theta}_{\mathrm{head}}^{(\mathrm{Beh})}} L_{\mathrm{Beh}}, \\
 \mathbf{g}_{\mathrm{head}}^{(\mathrm{ReID})} &= \nabla_{\boldsymbol{\theta}_{\mathrm{head}}^{(\mathrm{ReID})}} L_{\mathrm{ReID}}.
\end{align}

To monitor optimization dynamics throughout training without biasing model selection, the E4 training loop computes diagnostic metrics before and after projection at every super-step. For each task pair $(i, j)$, these include the unprojected inner product $\mathbf{g}_i^\top \mathbf{g}_j$, the unprojected cosine similarity $\cos(\mathbf{g}_i, \mathbf{g}_j) = \frac{\mathbf{g}_i^\top \mathbf{g}_j}{\lVert\mathbf{g}_i\rVert_2 \lVert\mathbf{g}_j\rVert_2}$, the binary conflict indicator $\mathbb{I}(\mathbf{g}_i^\top \mathbf{g}_j < 0)$, the gradient norms before and after projection, the total number of conflict projections triggered per super-step, and the post-projection cosine similarities. These diagnostics permit direct measurement of shared-backbone gradient-direction conflict during E4 training. \subsection{Multi-Task Joint Optimization Protocol}

Because cattle datasets from different farms and recording modalities do not contain overlapping annotations across body condition, behavior sequences, and individual identities, joint multi-task training cannot employ single multi-label batches. Instead, an interleaved mini-batch schedule is executed.

Each optimization step is structured as a multi-task super-step comprising three sequential forward and backward passes:
\begin{enumerate}
 \item \textbf{BCS mini-batch}: A batch of $B_{\mathrm{BCS}} = 64$ samples is passed through the model. The ordinal binary cross-entropy loss $L_{\mathrm{BCS}}$ is computed, and gradients are backpropagated into the active parameters.
 \item \textbf{Behavior mini-batch}: A batch of $B_{\mathrm{Beh}} = 8$ video sequences (64 total frames) is passed through the model. The categorical cross-entropy loss $L_{\mathrm{Beh}}$ is computed, and gradients are backpropagated.
 \item \textbf{Re-ID mini-batch}: A batch of $B_{\mathrm{ReID}} = 32$ images is passed through the model. The identity cross-entropy loss $L_{\mathrm{ReID}}$ is computed, and gradients are backpropagated.
 \item \textbf{Parameter update}: In the monolithic control (E1) and modular architecture (E3), shared backbone gradients are accumulated directly by standard summation ($\mathbf{g}_{\mathrm{shared}} = \sum_t \nabla_{\boldsymbol{\theta}_{\mathrm{shared}}} L_t$) before a single AdamW parameter update. In the PCGrad optimization control (E4), task gradients on the shared backbone are captured independently, pairwise conflicts are projected via PCGrad, and the projected gradients are summed ($\mathbf{g}_{\mathrm{shared}} = \sum_t \mathbf{g}'_t$) before a single AdamW parameter update, with task-head gradients remaining unmodified.
\end{enumerate}

Equal task weighting is enforced throughout training:
\begin{equation}
 w_{\mathrm{BCS}} = w_{\mathrm{Behavior}} = w_{\mathrm{ReID}} = 1.0.
\end{equation}
Training runs for 30 epochs with 538 super-steps per epoch (16,140 total super-steps). This schedule is defined by the complete ScienceDB BCS training population ($N = 34{,}369$ images; batch size $B_{\mathrm{BCS}} = 64$), where $\lceil 34{,}369 / 64 \rceil = 538$ batches per epoch establish the super-step cadence across all three tasks. Optimization uses AdamW with an initial learning rate of $\eta_0 = 10^{-4}$, weight decay of $10^{-4}$, and a cosine annealing learning-rate schedule decaying to $\eta_{\min} = 10^{-6}$.

Model checkpoint selection is determined strictly by minimizing the predefined mean validation loss objective:
\begin{equation}
 L_{\mathrm{MTL,val}} = \frac{1}{3}\left( L_{\mathrm{BCS,val}} + L_{\mathrm{Behavior,val}} + L_{\mathrm{ReID,val}} \right).
\end{equation}
Held-out test sets were excluded from training, hyperparameter tuning, threshold calibration, and checkpoint selection according to the implemented evaluation protocol. Table~\ref{tab:mtl_training_protocol} outlines the per-task batch parameters and joint optimization hyperparameters.

\subsection{Architectural Gradient Isolation and Claim Boundaries}

The mathematical distinction in gradient routing across the three executed multi-task configurations is formal and structural:
\begin{itemize}
 \item In the \textbf{monolithic hard-shared control (E1)}, the parameter vector of the shared backbone $\boldsymbol{\theta}_{\mathrm{shared}}$ directly receives gradient contributions from all three task loss functions:
 \begin{equation}
  \mathbf{g}_{\mathrm{shared}} = \nabla_{\boldsymbol{\theta}_{\mathrm{shared}}} L_{\mathrm{BCS}} + \nabla_{\boldsymbol{\theta}_{\mathrm{shared}}} L_{\mathrm{Beh}} + \nabla_{\boldsymbol{\theta}_{\mathrm{shared}}} L_{\mathrm{ReID}}.
 \end{equation}
 Each task head $\boldsymbol{\theta}_{\mathrm{head}}^{(t)}$ receives gradients solely from its own loss $L_t$.
 \item In the \textbf{modular task-private model (E3)}, the shared backbone $\boldsymbol{\theta}_{\mathrm{shared}}$ intentionally receives accumulated gradients from all three tasks through the residual connection:
 \begin{equation}
  \mathbf{g}_{\mathrm{shared}} = \sum_{t \in \{\mathrm{BCS}, \mathrm{Beh}, \mathrm{ReID}\}} \nabla_{\boldsymbol{\theta}_{\mathrm{shared}}} L_t.
 \end{equation}
 In contrast, each task-private adapter $\boldsymbol{\theta}_{\mathrm{adapter}}^{(t)}$ and task head $\boldsymbol{\theta}_{\mathrm{head}}^{(t)}$ receive gradient signals strictly from their corresponding task loss $L_t$, with $\nabla_{\boldsymbol{\theta}_{\mathrm{adapter}}^{(t)}} L_{t'} = \mathbf{0}$ for all $t' \neq t$.
 \item In the \textbf{gradient-projected hard-shared control (E4)}, the architecture is identical to E1, but the shared backbone parameter vector $\boldsymbol{\theta}_{\mathrm{shared}}$ receives the sum of pairwise conflict-projected task gradients:
 \begin{equation}
  \mathbf{g}_{\mathrm{shared}} = \mathbf{g}'_{\mathrm{BCS}} + \mathbf{g}'_{\mathrm{Beh}} + \mathbf{g}'_{\mathrm{ReID}},
 \end{equation}
 while each task head $\boldsymbol{\theta}_{\mathrm{head}}^{(t)}$ receives its unmodified, unprojected task-specific gradient $\nabla_{\boldsymbol{\theta}_{\mathrm{head}}^{(t)}} L_t$.
\end{itemize}

The gradient separation originates from the model architecture and training procedure. The gradient of one task head is isolated from the other to prevent its direct impact on the private adapter of another task. In E4, the conflicting part of the shared-backbone gradients is projected. However, such a technique neither theoretically guarantees that there would be no gradient conflict in the shared backbone nor ensures that there would be no negative transfer. The actual impact of the above-discussed routing and optimization techniques on the performance of generalization across the three tasks is analyzed through experiments in Chapter 5. In the system architecture, the process of multi-task super-step, gradient combination, and their separation is illustrated.

\subsection{Evaluation Metrics and Protocol Harmonization}

The BCS is assessed with MAE of physical score, Acc@0 (exact accuracy), Acc@1 (accuracy of predicting one neighboring class or up to $\pm$0.25 BCS units), balanced accuracy, and Macro-F1. For $N$ samples,
\begin{equation}
 \mathrm{MAE}_{\mathrm{BCS}}=\frac{1}{N}\sum_{i=1}^{N}|s_i-\hat{s}_i|.
\end{equation}

The behavioral analysis is conducted with overall accuracy, balanced accuracy, Macro-F1, per-class precision, recall, and F1, besides other source-specific scores. Balanced accuracy refers to the mean value of recall for the five classes; thus, it is useful for imbalanced data sets.

The metric to evaluate the performance of Re-ID system is known as Rank-k that determines the percentage of queries for which at least one correct identity is found in the first k gallery search results. Average Precision determines the quality of rankings attained by each query individually, whereas the mAP determines the average of all these Average Precision values. Barn-to-Parlor and Snapshots-to-Parlor are evaluated using the same parlor gallery of 36,811 images.

In order to maintain comparability, E1, E3, and E4 are evaluated using the same test population as the benchmark systems. The test datasets contain 7,549 images from ScienceDB test images for BCS, 780 retained video sequences for Behavior Recognition, and 69 unseen cattle identities for SideView Protocol A. The test population for Re-ID contains 25,260 barn queries and 607 snapshot queries.
